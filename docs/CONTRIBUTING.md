# Contributing

Audora is intended to be developed in the open under Apache License 2.0. During the design phase, contributions should improve or clarify these documents; implementation contributions should follow after phase 1 validates the architecture.

## Before contributing

- Check the issue tracker and roadmap for related work.
- For product behavior changes, describe the user problem and acceptance criteria.
- For architectural, security, privacy, licensing, packaging, or persistence changes, propose an ADR or update the relevant design document first.

## Pull requests

Keep changes focused, explain the rationale, list validation performed, and identify platform-specific or migration effects. Do not include proprietary media or personal data in examples, fixtures, screenshots, or logs. Follow the [coding conventions](CODING_CONVENTIONS.md) and [Git conventions](GIT_CONVENTIONS.md).

## Conduct and project governance

Contributors are expected to communicate respectfully and focus critique on work. Before accepting external contributions, maintainers should adopt a recognized Code of Conduct and publish maintainer roles, decision process, and security contact. Contribution licensing/CLA policy must be selected and documented before the first external code contribution; do not imply that a CLA is currently in effect.
